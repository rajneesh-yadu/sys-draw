# engine

Analytical simulation: compile → load → route → M/M/c queueing → latency composition → `SimResult` with explain strings. Pure TS, no React, deterministic; runs in a Web Worker (Comlink).

- **Depends on:** `core`, `registry` · **Built in:** S07 (scaling + cost: S09, geo: S10, failures over time: S11, provider prices/limits: S12, deep component behaviors + Zipf cache: S13)

## Model

Each replica is an M/M/c queue (c = `perf.maxConcurrencyPerInstance`, μ = 1000/S̄ with S̄ the read/write-weighted service time) receiving λ/replicas. A flow is an expression tree (visit / seq / choice / async): explicit `path` steps in order, or — for a flow with an empty path, or no flows at all — a walk from client nodes along edges. Latencies of a path add as a shifted exponential (Σ means + RSS of tail excess); LB splits and cache hit/miss make a mixture whose percentiles are solved by bisection. Rejections (`saturationBehavior: reject`) reduce downstream load (fixed-point iteration); `queue` saturation adds backlog wait over `durationSec`; nodes are evaluated at ρ ≤ `rhoCap`.

**Scaling (S09).** Service times are measured on a component's first instance type; a size with k× vCPU divides them by f(k) (`linear` k, `sublinear`/`single-writer` Amdahl). A node's traffic is spread over instance pools: even replicas (hottest gets f = 1 + √(2 ln N/V) × average behind a consistent-hash LB); single-writer = 1 primary per shard with all writes + R read replicas sharing reads; S shards with the hottest taking max(skew, 1/S). The node reports its busiest instance's ρ. Autoscale = steady state ⌈work/(c·target)⌉ clamped to min/max. Cost = instances × $/h × provider multiplier × 730 (+ standbys), or busy instances (Little) for serverless, or requests × $/M for $0/h managed services, + storage GB × copies × $/GB-month; volumes use peak ÷ peakMultiplier.

**Geo (S10).** Active once a node sits in a Region group with a known region (provider `regions`, else generic). Load is per user region (λ_r = users_r × rpsPerUser × share × peak × daily-cycle factor at the busiest UTC moment) and each region is routed separately: clients (geo-DNS, DNS `routingPolicy`), LBs and CDNs with targets in several regions pick the nearest healthy one (`regionOutage`/region `groupOutage` events = down); reads to copies of the same data store go to the nearest. Each hop pays RTT = 2 × 1.5 × d / 200 km/ms + 1 ms (+ user last mile); unplaced nodes sit with their caller; CDN/DNS sit at an edge PoP by the user. Edges get mean RTT, egress cost (internet, inter-region × 0.25) and, store → store, replication lag = RTT/2 + Wq + S_write. Reads never cross store → store edges.

**Failures over time (S11).** 1 s ticks (⌈D/600⌉ s for long runs); each tick = `evaluate` under that tick's conditions, state carried over: nodes down (node/AZ/group/region events) fail every call; LBs drop a dead target after `healthCheckIntervalSec × unhealthyThreshold` (10 × 3 = 30 s) if a target is still up; clients leave a dead region after the DNS TTL (60 s); spikes scale routed rps; packet loss adds (1 − (1 − p)^⌈B/1460⌉) × 200 ms per hop; latency injection adds fixed ms (edge, or node answers without using capacity); dependency slow multiplies service time; hot key raises the hottest shard's share; disk full fails writes; cold starts add coldStartMs × (1 − elapsed/D) per request; partitions cut cloud ↔ cloud hops. Edges: retries ⇒ λ × A with A = (1 − (1 − a)^(r+1))/a, success 1 − (1 − a)^(r+1); timeouts P = e^(−τ/T̄); circuit breakers open at the configured failure ratio over 10 s, fail fast for `breakerOpenSec` (30), then one half-open trial tick. `queue` saturation carries a backlog (λ − capacity per second, wait = backlog/capacity). Autoscaling: target tracking per tick, warm-up delay, 60 s scale-in cooldown. Unchanged ticks reuse the previous evaluation; queueing results are cached per node + rps. API: `simulate` adds `timeline` + `timelineEvents` (+ `engine.chaos` findings) when the scenario has events (`EngineOptions.timeline`, `maxTimelineTicks` 600). `runTimeline(input)`; `evaluate(model, routed, options, durationSec, perturbation?, seedErrors?, queueCache?)` (steps 4–6, shared by the analytical run and every tick); `expectedAttempts`, `retrySuccess`, `timeoutProbability`, `RETRY_BACKOFF_BASE_MS`; chaos helpers `eventWindow`, `isActive`, `eventLabel`, `packetLossDelayMs`/`packetLossExplain`, `nodesInGroup`, `healthCheckDelaySec`, `dnsTtlSec` and their constants. `CompiledEdge.config`, `NetHop.ends`.

**Deep components (S13).** A behavior may `tune` a node at compile time from its config (`compile.tuneNode`, in behavior order): `serviceTimeMs` = the WORK a request puts on the node (ρ, capacity), new optional `CompiledNode.responseServiceMs` = what the caller waits for besides Wq (quorum order statistics, acks, sync replication); also `scale` and `serversPerInstance`. Behaviors: `cache` (Zipf hit rate: LFU H(C,s)/H(N,s), LRU Che, random; capacity from instance memory × shards; `hitRate` config still overrides), `queue` (work queue; with `partitions` = a log: each consumer node is a consumer group, parallelism min(instances, P), hottest partition on one consumer, lag + time behind, retention vs disk, write work × RF), `quorum` (N/R/W: work R·S_r / N·S_w, wait slowest of R / W-th of N, vnodes ring imbalance), `consensus` (leader + majority commit, local vs linearizable reads), `partitionedKv` (3 000 RU / 1 000 WU per partition, 10 GB splits, GSIs, throttling), `relational` (index on/off seq scan, index write cost, sync replication), `replicaReads` (readPreference), `scatterGather` (search over all shards, wait H_P), `columnar` (scan rows × columns ÷ cores, small-insert warning), `podPacking` (pods per node from requests), `metricsStore` (series → ingest, storage, memory), `configPerf` (generic: applies `.meta({ perfEffect })` declared on config fields). Math: `behaviors/lib/` (order-stats, zipf, perf-effects, config).

## Layout

- model/ — types, compile, load, route, expr, latency · queueing/ — mmc, node · behaviors/ — one file per behavior · simulate.ts (one run) · worker.ts + worker-api.ts + client.ts (Comlink) · test-fixtures.ts (tests only) · scaling/ — vertical, pools, roles, spec, autoscale · cost/ — cost.ts · geo/ — distance, diurnal, places, routing · chaos/ — events.ts (event timing, targets, delays), timeline.ts (tick loop) · model/evaluate.ts (shared steps 4–6)

## Extension points

- New behavior = `behaviors/<id>.ts` exporting `behavior = defineBehavior({ id, tune?, routeOut?, routeRest?, cacheAsideHitRate?, hashVirtualNodes?, finish?, placement?, geoRoutes?, dnsPolicy? })`; auto-discovered, matched by `ComponentDefinition.behaviors`. Helpers go in `behaviors/lib/` (not auto-discovered). After adding a behavior file, clear `node_modules/.vitest-cache` if a test does not see it (vitest's module cache keeps the old glob expansion).
- Scaling is data-driven: tag config fields with `.meta({ scaling: role })` (roles in `scaling/roles.ts`: shards, keySkew, readReplicas, standby, storageGb, storageCopies, maxInstances, minInstances).
